STEP 02

把插件放对位置

安装 ws-Adapter

在哪里执行？

打开 TRSS-Yunzai 所在目录，再打开 PowerShell 或终端。命令中的 TRSS-Yunzai 要替换为你的实际目录名。

PowerShell
cd .\TRSS-Yunzai\plugins
git clone https://github.com/ShiYuPIay/ws-Adapter-plugin.git
cd .\ws-Adapter-plugin
npm install --omit=dev
Terminal
cd TRSS-Yunzai/plugins
git clone https://github.com/ShiYuPIay/ws-Adapter-plugin.git
cd ws-Adapter-plugin
npm install --omit=dev
安装成功后应当看到
TRSS-Yunzai/
└─ plugins/
   └─ ws-Adapter-plugin/
      ├─ apps/
      ├─ components/
      ├─ config/
      └─ package.json
提示“目录已经存在”怎么办？

不要再次克隆。进入原来的 ws-Adapter-plugin 目录，依次执行 git pull 和 npm install --omit=dev。

提示找不到 git 或 npm 怎么办？

git 不存在时安装 Git；npm 不存在时安装 Node.js 18 或更高版本。安装后关闭并重新打开终端再试。

最后一行没有红色报错即可继续。

STEP 03

让网关开始监听

重启并激活插件

  1. 1
    完整重启 TRSS-Yunzai

    第一次安装时不能依靠 QQ 命令重载，因为此时 QQ 通信还没有接通。

  2. 2
    等待自动生成配置

    文件位置：plugins/ws-Adapter-plugin/config/config.yaml

  3. 3
    寻找启动日志

    看到下面整行文字，说明端口已经开始监听。

TRSS-Yunzai console
[启动] [ws-Adapter] 网关已启动，绑定 0.0.0.0:6099/ws；SnowLuma 同机目标 ws://127.0.0.1:6099/ws
为什么这里出现 0.0.0.0？

0.0.0.0 是插件的“监听范围”，不是让 SnowLuma 填写的目标地址。SnowLuma 目标 URL 永远不要写 0.0.0.0。

没有这行日志？先检查插件目录和依赖安装。

STEP 04

这是唯一需要做的网络选择

SnowLuma 和 TRSS 在哪里？

选择最符合你的情况的一项。页面会据此生成 SnowLuma 的目标 URL。

查看 docker-compose.yml 中 services: 下方的名称。
填写 SnowLuma 所在设备能够访问到的地址，不要填 127.0.0.1。
SNOWLUMA 目标 URLws://127.0.0.1:6099/ws
同机说明

127.0.0.1 表示“这台电脑自己”。不需要开放防火墙端口。

插件自身仍固定绑定 0.0.0.0:6099/ws。

REFERENCE

容器用户看这里

Docker 接线说明

SnowLuma 容器reverse-ws
ws://trss-yunzai:6099/ws
TRSS 容器ws-Adapter

同一 Docker 网络中，地址应使用 TRSS 的服务名，不能使用 127.0.0.1。因为容器里的 127.0.0.1 只指向该容器自己。

跨网络或宿主机访问时发布端口
services:
  trss-yunzai:
    ports:
      - "6099:6099"

SnowLuma 不需要访问 TRSS 内部的 2536 端口；ws-Adapter 在 TRSS 环境内部连接它。

GLOSSARY

不会术语也能接通

八个词的白话解释

reverse-ws
由 QQ 客户端一侧主动拨号连接外部服务器。在这里，主动方是 SnowLuma。
监听
像打开一扇门等待别人进来。插件在所有网卡的 6099 端口等待 SnowLuma。
目标 URL
SnowLuma 要拨到的完整门牌，包括协议、主机、端口和路径。
0.0.0.0
只用于服务端监听，意思是接受所有网卡连接；不能当作客户端目标。
Token
连接时核对的共同口令。三处原始内容相同，TRSS 配置额外带 Bearer 前缀。
lifecycle
SnowLuma 连接后发出的“我是谁”事件，TRSS 据此登记 QQ 账号。
action
TRSS 要求 SnowLuma 执行的动作，例如向 QQ 发送一条消息。
echo
请求和响应共用的编号，让 TRSS 知道这条结果属于哪次动作。
